# 微信语音复制 v0.2.2

适配微信输入法 Windows 3.0.0.34，修复输入法更新后复制工具拒绝连接的问题。保留 2.1.4.6 支持。

- 为两个精确程序文件分别配置语音对象、状态、最终文字、完成和取消标记的位置，继续按 SHA-256 校验后读取。
- 提取正式程序和测试共用的快照读取器，并复查读取前后的对象、状态、轮次和完成标记，丢弃正在变化的数据。
- 新增七组快照回归检查，结合原有八组轮次检查，覆盖两版结构、UTF-8、取消、无效数据和读取期间的状态变化。
- 连接成功的托盘状态和只读诊断报告显示所匹配的输入法版本，便于确认适配是否生效。

正常结束语音后，光标在输入框内或外都应更新 Windows 剪贴板。输入法自身的直接送字、剪贴板输出和本工具的复制是不同步骤；远程软件负责之后的跨设备粘贴。

## 使用

- `WeTypeVoiceCapture-v0.2.2-win-x64.exe`：直接运行的单文件程序。
- `wetype-voice-clipboard-v0.2.2-win-x64.zip`：程序、说明和许可证。
- `SHA256SUMS.txt`：本次构建的文件校验值。

先退出旧实例，再启动新版。已有开机启动设置会更新到新版路径。首次使用不会自动启用开机启动。

## 验证情况

本地构建、15 组回归检查、发行包检查、真实 3.0.0.34 只读连接，以及隔离注册表中的启动配置检查通过。
用户完成输入框内、输入框外两轮本地语音后，新版成功复制计数由 0 增至 2；最后一轮剪贴板内容与输入法最终文字一致。
向日葵远端 Mac 两轮粘贴也经用户确认得到对应的新内容；同期本机只读观测到的 8 个完成轮次均成功写入与最终转写一致的剪贴板内容。
本轮未重新验证真人取消、输入法重启、长期运行，以及各种 Ctrl / Command 键位映射。完整测试记录见 [验证记录](https://github.com/lzhshen/wetype-voice-clipboard/blob/v0.2.2/docs/validation.md)。

## 兼容范围

Windows 10/11 x64，.NET Framework 4.8；微信输入法 2.1.4.6 / 3.0.0.34，且目标程序通过内置校验。
这是非官方兼容工具，不是 macOS 原生程序；Mac 可作为远程粘贴目标。程序目前未进行代码签名。
工具自身不联网、不录音、不保存转录正文，不更改语音快捷键或输入焦点。

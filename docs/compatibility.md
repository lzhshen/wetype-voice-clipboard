## 为什么需要逐版本适配

微信输入法会在运行内存中保存当前语音轮次、识别状态及最终文字。
本工具按经过验证的程序文件选择对应结构，通过 Windows 的只读进程接口读取它们。
这些内部结构不是公开承诺稳定的接口，版本变化后可能移动或改变含义。

连接时先校验文件，再查找唯一且通过结构检查的对象。
读取期间校验指针、状态、长度及字符串稳定性，丢弃正在变化的快照。
输入法关闭或对象失效时会重新连接，版本不符时提示需要适配。

定位信息位于 `src/VoiceSnapshotReader.cs` 的 `VoiceLayout`；快照校验由 `VoiceSnapshotReader` 完成，`Source` 负责只读进程访问和对象定位。

| 数据 | 2.1.4.6 | 3.0.0.34 |
| --- | --- | --- |
| VoiceBridge 主虚表 RVA | `0xFEAE58` | `0x10B9A80` |
| 会话管理器，相对 VoiceBridge | `+0x158` | `+0x168` |
| 引擎包装对象，相对会话管理器 | `+0x78` | `+0x78` |
| 引擎状态，相对引擎包装对象 | `+0x48` | `+0x58` |
| 最终文字，相对引擎包装对象，UTF-8 | `+0x100` | `+0x160` |
| 完成标记，相对会话管理器 | `+0xAB0` | `+0xC98` |
| 轮次标识，相对会话管理器 | `+0xB08` | `+0xCF0` |
| 取消标记，相对 VoiceBridge | `+0x6A8` | `+0x6C8` |
| 结束处理中标记，相对 VoiceBridge | `+0x6B0` | `+0x6D0` |

这些偏移只适用于上表中的精确程序文件，不应直接用于其他版本。

3.0.0.34 的定位依据包括 VoiceBridge 的 RTTI / 构造函数、`initSessionManager`（RVA `0x917290`）、引擎包装及内部引擎构造函数，以及 `emitFinishedOnce`（RVA `0x9A0E90`）对完成标记和轮次字符串的引用。取消和结束标记位于 VoiceBridge `+0x5B8` 的内嵌控制对象中，分别是该对象 `+0x110` 和 `+0x118`。

## 输入焦点与剪贴板

3.0.0.34 的 `deliverFinalText`（RVA `0x94B1B0`）包含直接送字和仅剪贴板输出的分支；焦点、目标应用等状态会影响输入法自身的输出路径。
复制不依赖输入焦点：只要观察到一轮未取消的语音正常完成、结果稳定，就复制到 Windows 剪贴板。可选自动粘贴单独检查前台窗口，不切换焦点。
v0.2.4 起，`ClipboardTextWriter` 先准备完整的 `CF_UNICODETEXT` 内存，再通过隐藏的消息窗口，在一次 `OpenClipboard` / `CloseClipboard` 事务内发布。避免 `Clipboard.SetDataObject(..., true)` 的 OLE 设置和刷新阶段产生两次变化通知，以及首次通知时剪贴板仍被刷新阶段占用的窗口。消息窗口不激活、不切换焦点；写入失败仍由现有轮次逻辑重试。
输入框内外都应更新剪贴板；远端粘贴还依赖远程软件的同步。
版本不匹配时，本工具停止读取，此时仍有可能看到输入法自己的剪贴板输出，不能据此认定本工具正常。

## 可选自动粘贴（v0.3.0）

`AutoPasteController` 只在观察到新轮次且开启选项时获取目标；启动/恢复/对象变化时已经进行中的语音只保留原复制行为。复制成功才安排 750ms 后的一次粘贴，读取剪贴板遇到占用最多再等 2 秒；已经发送过或发送失败的按键均不重发。

`WindowsPasteDesktop` 核对 `AweSun` 进程、可见前台窗口及 `FlutterMultiWindow` / `ORAY_FLUTTER_VIEW_CONTAINER` 配对结构（同进程、同标题）。主界面 `FLUTTER_RUNNER_WIN32_WINDOW` 不放行。该识别来自当前安装客户端的只读窗口枚举，不宣称兼容所有向日葵版本；窗口标题仅在内存中比较。

开启后通过进程外 `SetWinEventHook` 监听前台及桌面切换，关闭时解除监听。切走再切回也取消，发送前再次核对窗口、剪贴板 Unicode 正文/序列号和最后输入时间；修饰键或 V 已按下时不发送。模拟 Ctrl+V 的结构按 x64 INPUT 布局定义，使用物理左 Ctrl 扫描码和前台键盘布局对应的 V 扫描码（`KEYEVENTF_SCANCODE`）。原 VK-only 方式在真实低层事件中产生 `scan=0`，原生键盘检查能捕获这一差异，但用户确认仅修正扫描码仍会在远端出现单独的 V。

`PasteKeySequence` 通过现有消息循环定时器分阶段执行：按下 Ctrl，约 100ms 后发送一次 V 按下/释放，再约 100ms 后松开 Ctrl。其间不阻塞窗口事件处理，持续核对前台窗口和剪贴板序列号；临时低层键鼠监听器区分本程序标记的注入与外部操作，外部操作取消后续阶段。监听只保存中断标记和用于避免误释放用户按键的 Ctrl/V 状态，不保存正文、按键历史或坐标，完成/取消后即解除。部分发送只补释放本程序仍拥有的按键，不再次按 V，不发送 Enter。原生测试在接收窗口处理 V 时读取 Ctrl 的实际异步状态，已复现一次性发送全部事件时 Ctrl 提前松开，分阶段发送后该检查通过；这不等于已经证实向日葵内部的处理方式。

远程同步没有可用的确认接口，本机固定等待不能保证任意网络延迟下的远端就绪。状态区分“复制成功”与“已触发粘贴”；不把 Windows 接受输入事件等同于远端内容成功。目标远端的文本框及插入点由用户选择，本程序不读取远端控件树。

原生行为依据：[SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)、[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)。

## 更新适配时的要求

不能只替换文件校验值来接受新版本。需要重新验证结构含义和实际输入行为：

1. 正常完成时复制最终整理结果，每轮只复制一次。
2. 启动工具时跳过此前已经结束的旧结果。
3. 输入法实际取消语音时，工具不复制该轮结果。
4. 本地输入框、无输入焦点以及远程控制窗口前台的行为。
5. 输入法重新启动、剪贴板短时占用、版本不匹配等情况。

维护验证只检查必要状态。不要收集完整内存转储、账号信息或用户的语音历史，也不要用写内存或自动切换焦点来掩盖适配问题。

## 只读诊断

```powershell
Start-Process .\WeTypeVoiceCapture.exe -ArgumentList '--probe', '.\probe.txt' -Wait
Get-Content .\probe.txt
```

诊断文件仅包含是否定位成功、匹配的输入法版本、当前状态及文字长度，不包含识别文字。
诊断不开始或结束语音、不改变焦点、不写入剪贴板。

## 验证范围

2.1.4.6 和 3.0.0.34 均已有 Windows 宿主机通过向日葵向远端 Mac 粘贴的人工验证结果。3.0.0.34 的验收结合了用户两轮实际粘贴反馈与本机只读状态核对。逐版本验证范围见 [验证记录](validation.md)。
其他远程软件、Windows ARM64、其他输入法版本及所有异常路径尚未穷尽验证。
CI 主要检查构建与发行包，不能代替安装真实输入法后的人工语音测试。

## 为什么需要逐版本适配

微信输入法会在运行内存中保存当前语音轮次、识别状态及最终文字。
本工具按经过验证的程序文件选择对应结构，通过 Windows 的只读进程接口读取它们。
这些内部结构不是公开承诺稳定的接口，版本变化后可能移动或改变含义。

连接时先校验文件，再查找唯一且通过结构检查的对象。
读取期间校验指针、状态、长度及字符串稳定性，丢弃正在变化的快照。
输入法关闭或对象失效时会重新连接，版本不符时提示需要适配。

定位信息位于 `src/VoiceSnapshotReader.cs` 的 `VoiceLayout`；快照校验由 `VoiceSnapshotReader` 完成，`Source` 负责只读进程访问和对象定位。

| 数据 | 2.1.4.6 | 3.0.0.34 |
| --- | --- | --- |
| VoiceBridge 主虚表 RVA | `0xFEAE58` | `0x10B9A80` |
| 会话管理器，相对 VoiceBridge | `+0x158` | `+0x168` |
| 引擎包装对象，相对会话管理器 | `+0x78` | `+0x78` |
| 引擎状态，相对引擎包装对象 | `+0x48` | `+0x58` |
| 最终文字，相对引擎包装对象，UTF-8 | `+0x100` | `+0x160` |
| 完成标记，相对会话管理器 | `+0xAB0` | `+0xC98` |
| 轮次标识，相对会话管理器 | `+0xB08` | `+0xCF0` |
| 取消标记，相对 VoiceBridge | `+0x6A8` | `+0x6C8` |
| 结束处理中标记，相对 VoiceBridge | `+0x6B0` | `+0x6D0` |

这些偏移只适用于上表中的精确程序文件，不应直接用于其他版本。

3.0.0.34 的定位依据包括 VoiceBridge 的 RTTI / 构造函数、`initSessionManager`（RVA `0x917290`）、引擎包装及内部引擎构造函数，以及 `emitFinishedOnce`（RVA `0x9A0E90`）对完成标记和轮次字符串的引用。取消和结束标记位于 VoiceBridge `+0x5B8` 的内嵌控制对象中，分别是该对象 `+0x110` 和 `+0x118`。

## 输入焦点与剪贴板

3.0.0.34 的 `deliverFinalText`（RVA `0x94B1B0`）包含直接送字和仅剪贴板输出的分支；焦点、目标应用等状态会影响输入法自身的输出路径。
本工具不判断或修改输入焦点：只要观察到一轮未取消的语音正常完成、结果稳定，就复制到 Windows 剪贴板。
输入框内外都应更新剪贴板；远端粘贴还依赖远程软件的同步。
版本不匹配时，本工具停止读取，此时仍有可能看到输入法自己的剪贴板输出，不能据此认定本工具正常。

## 更新适配时的要求

不能只替换文件校验值来接受新版本。需要重新验证结构含义和实际输入行为：

1. 正常完成时复制最终整理结果，每轮只复制一次。
2. 启动工具时跳过此前已经结束的旧结果。
3. 输入法实际取消语音时，工具不复制该轮结果。
4. 本地输入框、无输入焦点以及远程控制窗口前台的行为。
5. 输入法重新启动、剪贴板短时占用、版本不匹配等情况。

维护验证只检查必要状态。不要收集完整内存转储、账号信息或用户的语音历史，也不要用写内存或自动切换焦点来掩盖适配问题。

## 只读诊断

```powershell
Start-Process .\WeTypeVoiceCapture.exe -ArgumentList '--probe', '.\probe.txt' -Wait
Get-Content .\probe.txt
```

诊断文件仅包含是否定位成功、匹配的输入法版本、当前状态及文字长度，不包含识别文字。
诊断不开始或结束语音、不改变焦点、不写入剪贴板。

## 验证范围

2.1.4.6 和 3.0.0.34 均已有 Windows 宿主机通过向日葵向远端 Mac 粘贴的人工验证结果。3.0.0.34 的验收结合了用户两轮实际粘贴反馈与本机只读状态核对。逐版本验证范围见 [验证记录](validation.md)。
其他远程软件、Windows ARM64、其他输入法版本及所有异常路径尚未穷尽验证。
CI 主要检查构建与发行包，不能代替安装真实输入法后的人工语音测试。
